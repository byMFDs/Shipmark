# Аудит довіри (Етап 1), 2026-11-12

Мета: зрозуміти, наскільки легко видати чужий або скопійований repo чи сайт за свій проєкт.
Ми перевіряємо **володіння repo, контроль домену і uptime**. Хто написав код, ми не перевіряємо й не стверджуємо.
Код під час аудиту не змінювався. Атаки перевірено тимчасовими тестами з моками GitHub/DNS/HTTP (18 тестів, потім видалені).

## 1. Що перевіряється зараз

**Repo owner (`authored`)**: `verification/repo.py`, правило в `projects/proof.py::_authored`.
- Запускається **тільки вручну**: кнопка "Check" (`projects/views.py::repo_check`), 1 раз на 10 хв на проєкт.
- Хто ти: `SocialAccount.uid` (числовий GitHub id з входу). Порівнюється **id, не login**. Добре.
- `GET /repos/{owner}/{name}`: беремо `id`, `full_name`, `private`, `fork`, `owner.id`, `owner.type`.
  Private відхиляється. `is_owner = owner.id == мій id AND owner.type == "User" AND NOT fork`.
- `GET /repos/.../contributors` (до 5 сторінок по 100): шукаємо свій id, беремо `contributions`.
- `GET /repos/.../commits?author=<login>&per_page=1` (+ остання сторінка): дати першого/останнього коміту.
- Заробляється, якщо `is_owner` **або** `contributions >= 10` (`MIN_AUTHORED_COMMITS`, константа в proof.py).
- Зберігається `RepoLink` (лише при успіху): ім'я, `github_repo_id` (unique), is_owner, кількість комітів,
  дати, `checked_at`, `earned_at`. Id власника repo **не зберігається**.
- Помилки GitHub (rate limit, 5xx, таймаут, 25 с на всю перевірку) нічого не змінюють: fail-closed. Добре.
- **Повторної перевірки за розкладом немає.** Mark живе вічно, поки власник сам не натисне "Check" з
  поганим результатом або не змінить назву repo в проєкті. Зняття mark не пишеться в AuditLog.
- `User.github_login` записується лише при першому вході (`accounts/adapters.py::populate_user`), далі не оновлюється.

**Live**: `verification/domain.py`.
- Токен: `secrets.token_hex(16)`, один рядок на проєкт+домен, `token` unique. Чужий токен не підходить.
- DNS: TXT `shipmark-verify=<token>` на точному хості (для `www.` також на голому домені).
- Meta: тег на `/` через `safe_fetch`; кінцевий хост після редиректів має збігатися з доменом.
- Один verified домен = один проєкт (частковий unique-індекс). `www.` ігнорується при порівнянні.
- Cron `reverify_domains` щодня: рядки, не підтверджені 30 днів, перевіряються тим самим методом.
  Тимчасова помилка: повтор до 35 днів. Остаточна: status=failed + AuditLog `hallmark.live.removed`.
- Live = verified і підтверджено за останні 35 днів, для домену з поточного `live_url`.

**Steady**: `verification/uptime.py`, cron `check_uptime` кожні 15 хв, кожен проєкт max раз на 3 год.
- HEAD (або GET) через `safe_fetch`; `ok = status < 400` після до 3 редиректів. Хост кінцевої
  адреси і вміст сторінки **не перевіряються**. Steady = Live + за 30 днів ≥40 перевірок і ≥95% ok.
- Зберігається час, ok, код, мс, код помилки. Чистка після 90 днів.

## 2. Тести атак

| # | Сценарій | Результат |
|---|---|---|
| a | Чужий repo, 0 комітів | BLOCKED |
| a | Чужий/орг repo, де в мене ≥10 комітів (дрібні PR) | **BYPASS**: mark "Repo owner" |
| b | Форк без своїх комітів | BLOCKED (`fork` знімає is_owner) |
| b | Форк + 10 порожніх комітів | **BYPASS**: шлях через ≥10 комітів |
| c | Zip чужого коду → новий свій repo, 1 коміт | **BYPASS**: власник за id |
| d | Копія з повною історією у свій repo | **BYPASS**: `created_at`, root SHA не читаються |
| e | Свій порожній repo / всі коміти за 1 день | **BYPASS**: власнику активність не потрібна |
| f | Login перейменовано, старий login зайняв інший | Repo-перевірка: BLOCKED (id). Профіль: **PARTIAL** (нижче) |
| g | Repo видалено і створено іншим / передано / private | **BYPASS**: ніхто не питає GitHub повторно |
| h | Чужий repo + свій домен | **BYPASS**: Live/Steady є, кнопка на чужий repo без позначки "не перевірено" |
| i | Домен (DNS-метод) потім редиректить на чужий хост | **BYPASS**: uptime "ok", reverify "confirmed" |
| i | Apex спільних хостів (github.io, vercel.app, …) | BLOCKED на практиці (токен туди не поставити), явної відмови немає |
| j | Один токен на кілька проєктів; двоє на один домен | BLOCKED |
| j | Двоє на один repo | BLOCKED, але **squatting**: контриб'ютор з 10 комітами займає repo першим, справжній власник отримує "taken" |
| k | Бот-коміти | BLOCKED для чужого repo (збіг за id); у своєму repo не важливо (див. e) |
| k | Підроблені email автора | У своїй копії переписана історія = "свої" коміти; у чужий repo без push-доступу не потрапити |
| l | Паркінг-сторінка / редирект рахуються як up | **BYPASS**: будь-яка відповідь <400 |

f, детально: після перейменування профіль далі веде на `github.com/<старий login>`, тобто на того, хто цей login
зайняв. Новий власник login не пройде реєстрацію: unique-обмеження на `github_login`. У тесті перевірено лише
обмеження БД (IntegrityError); чи буде це 500 у реальному потоці allauth, не перевірялось.

## 4. Оцінка запропонованих фіксів

- **Числовий id користувача**: уже є (`SocialAccount.uid`). Лишається оновлювати `github_login` при кожному вході
  (allauth оновлює `extra_data`, береться `login` з `GET /user`). Ціна: мала.
- **Id repo + id власника в RepoLink**: `id` уже зберігається, `owner.id` додати. Перевірка за id: `GET /repositories/{id}`
  (недокументований, але давно стабільний) ловить перейменування й передачу; 404 = видалено або private;
  ім'я → інший id = перестворено. Ціна: мала.
- **Відхиляти форки**: поле `fork` (+ `parent`, `source`) є в `GET /repos`. Закриває b. Ціна: дуже мала.
- **Імпортована історія**: `created_at` repo vs дата першого коміту (`commit.author.date` / `committer.date`).
  Сигнал справжній, але дати комітів задає сам автор (`git commit --date`, filter-repo). Ловить ліниві копії,
  не ловить ретельні. Тому лише "needs review", не автоматичний провал. Ціна: мала (+1 запит уже робимо).
- **Дублікат root SHA**: SHA першого коміту з останньої сторінки `/commits`. Порівняти можна **тільки серед
  RepoLink у нас**, не з усім GitHub (пошук `hash:` у Search API є, але індекс неповний і ліміт 30/хв;
  не раджу). Переписана історія змінює SHA. Корисно проти двох акаунтів з однією копією. Ціна: мала.
- **Статистика активності** `GET /repos/.../stats/contributors`: на автора `total` і `weeks[{w,a,d,c}]`
  (тиждень, додано, видалено рядків, коміти), `author.type` показує ботів, за документацією без merge-комітів.
  Віддає **202, поки рахує** (потрібен pending + повтор), для repo з ≥10 000 комітів a/d = 0.
  Порожні коміти видно як тижні з c>0 і a+d=0. Але дати знову задає автор, тож "N активних тижнів"
  підробляється скриптом. Підвищує зусилля, не доказ. Ціна: середня.
- **Зв'язок repo ↔ домен**: (1) поле `homepage` repo дорівнює верифікованому домену (змінює лише admin repo), або
  (2) файл-токен у repo через `GET /repos/.../contents/<path>` (потрібен push-доступ). Закриває h і "мій домен +
  чужий repo". Не закриває c/d: копія власна, туди можна покласти що завгодно. Ціна: мала–середня.
- **Щотижнева повторна перевірка repo**: 1–2 запити на repo, з `GITHUB_API_TOKEN` (5000/год) вистачить на тисячі.
  Закриває g. Ціна: мала.
- **Uptime: кінцевий хост = верифікований**: `FetchResult.url` і `redirects` уже є. Закриває i/l (редирект).
  Паркінг на тому ж хості без аналізу вмісту не розпізнати: це чесне обмеження. Ціна: мала.
- **Відмова для apex спільних хостів**: список у settings (Public Suffix List = нова залежність, не можна).
  Практичної дірки зараз немає, це радше зрозуміла помилка замість "токен не знайдено". Ціна: дуже мала.
- **Черга перевірки в адмінці** (unfold): потрібна для "needs review". Ціна: середня.
- **Панель "What was checked"**: лише факти з датами, без висновків про авторство. Ціна: середня (шаблон + 7 мов).

## 5. Що неможливо запобігти, і як це чесно сказати

Ніхто, крім автора, не знає, хто написав код. Копію чужого коду у власному repo з переписаною історією
(нові дати, свій email) GitHub не відрізнить від оригіналу, тож і ми не відрізнимо. Ми ускладнюємо лінивий обман
і показуємо факти; рішення лишається за читачем, а скарги розглядає модерація.

EN: "Shipmark checks facts it can prove: who owns the linked GitHub repository, who controls the domain, and
whether the site answers. It does not and cannot check who wrote the code. Commit history and dates are
written by the repository owner and can be changed. If you think a project is copied, report it."

UK: "Shipmark перевіряє лише те, що можна довести: кому належить пов'язаний GitHub-репозиторій, хто контролює
домен і чи відповідає сайт. Хто написав код, ми не перевіряємо й перевірити не можемо. Історію комітів і дати
пише власник репозиторію, і їх можна змінити. Якщо вважаєте, що проєкт скопійовано, поскаржтеся."

## 6. Рекомендований порядок

Порядок A–F з завдання підходить. Найбільше користі за найменшу ціну: відхилити форки (B), `reverify_repos` (D),
оновлювати `github_login` при вході (A). Окреме рішення для тебе: шлях "≥10 комітів у чужому repo" дає мітку
"Repo owner" людині, яка не власник. Варіанти: прибрати цей шлях; вимагати файл-токен у repo; або лишити зі
статистикою активності.
